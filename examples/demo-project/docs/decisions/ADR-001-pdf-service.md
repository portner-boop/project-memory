# Вынести генерацию PDF в отдельный сервис

## Контекст

Печатные формы отчётов верстаются сложной HTML-таблицей с шестью уровнями
вложенности. Рендер в Django требовал WeasyPrint и его системные зависимости
(cairo, pango) в основном образе backend, что раздувало образ и ломало сборку
при обновлении базового Debian.

## Решение

Отдельный сервис `pdf-service/` на FastAPI: принимает готовый JSON, подставляет
в Jinja-шаблон, отдаёт PDF. В базу не ходит, ничего не считает.

## Последствия

Плюсы:

- тяжёлые системные зависимости изолированы в одном образе;
- вёрстка печатных форм правится без релиза backend;
- шаблоны можно тестировать на фикстурах, без базы.

Минусы:

- две части системы вместо одной, нужен docker-compose даже локально;
- контракт JSON нигде не типизирован — ручка принимает сырой `dict`.

## Альтернативы

- **Рендер в Django через WeasyPrint** — отвергнуто из-за системных зависимостей.
- **Готовый SaaS для PDF** — отвергнуто: отчёты содержат персональные данные,
  наружу не отдаём.
- **Типизировать контракт через pydantic в сервисе** — отвергнуто сознательно:
  тогда backend не сможет добавить поле в JSON раньше обновления шаблона, и
  релизы придётся связывать. Свобода порядка релизов оказалась важнее.
