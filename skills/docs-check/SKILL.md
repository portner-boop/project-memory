# docs-check

Проверяет целостность документации и пересобирает каталог. Пересобирает `docs/_index.json` и сверяет документацию с кодом.

**Тут не нужно рассуждать** — это механическая сверка. Выполняй буквально,
ничего не додумывай.

---

## Шаг 1. Пересобрать `docs/_index.json`

Пройди по всем `.md` в `docs/` с frontmatter и собери:

```json
{
  "generated_by": "docs-check skill",
  "schema_version": 1,
  "documents": {
    "<id>": {
      "path": "docs/...",
      "type": "...",
      "code_paths": ["..."],
      "blocks": ["..."]
    }
  },
  "decisions": {},
  "tasks": {}
}
```

`blocks` — маркеры `<!-- block: … -->` **в порядке появления** в файле.
Порядок значим: по нему определяются границы блоков.

## Шаг 2. Проверки

Иди по списку, ничего не пропуская.

| # | Что проверяем | Как |
|---|---|---|
| 1 | ID документов уникальны | сравнить все `id:` |
| 2 | ID блоков уникальны внутри документа | сравнить маркеры |
| 3 | ссылки `path#Symbol` живые | файл существует, символ в нём есть |
| 4 | относительные markdown-ссылки живые | целевой файл существует |
| 5 | `code_paths` указывают на существующие пути | хотя бы одно совпадение по маске |
| 6 | у задач есть обязательные файлы | `request.md`, и если есть план — `progress.md` |
| 7 | frontmatter полный | `id` и `type` обязательны |
| 8 | нет пустых блоков | между маркером и следующим заголовком есть текст |
| 9 | `last_verified_commit` не протух | коммит существует в истории |
| 10 | нет конфликтующих ADR | два `accepted` по одному предмету |
| 11 | номера строк в постоянной документации | `file.py:142` — так нельзя |
| 12 | `AGENTS.md` не разросся | больше ~120 строк — предупреждение |

По пункту 3: если есть CodeGraph — `codegraph query <symbol>`. Нет — обычный
поиск по файлу.

По пункту 11: номера строк допустимы **только** в `docs/tasks/*/deep-dive.md`.
Это снимок кода на момент разбора. Везде ещё — ошибка.

## Шаг 3. Отчёт

Ошибки и предупреждения — раздельно. Ошибка ломает сборку, предупреждение нет.

```text
docs/_index.json пересобран: 12 документов, 47 блоков

❌ Ошибки (2)

  docs/architecture/backend.md
    строка 34: `backend/app/report/services.py#calc_total`
    → символ не найден; рядом есть `calc_total_expense` — переименовали?

  docs/product/reports.md
    блок REPORT.PDF пуст

⚠️ Предупреждения (2)

  docs/architecture/auth.md
    last_verified_commit a91d2f4 — 8 месяцев назад

  docs/tasks/DEMO-640/
    нет progress.md, хотя есть план

✅ Остальное чисто.
```

При ошибке по пункту 3 **предложи похожий существующий символ** — почти всегда
это переименование, и подсказка экономит минуту.

---

## Чего НЕ делать

- **Не чинить найденное молча.** Задача — сообщить. Правки только если
  попросили.
- Не считать ошибкой протухший `last_verified_commit` — это предупреждение.
- Не трогать содержимое документов при пересборке индекса.
- Не выдумывать проверок сверх списка.
