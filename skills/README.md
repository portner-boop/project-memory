# Скиллы

Скиллы — это **обычные markdown-файлы с инструкцией**. Агент их читает и делает
то, что там написано. Никакой программы с моделью внутри: думает тот агент,
за которого ты уже платишь.

## Установка

```bash
npx repomind-skills
```

В папке проекта. Разложит скиллы в `.agents/skills/` и сделает ссылки в
`.claude/skills/`, чтобы их видели и Claude Code, и Codex. Глобально ничего
не ставит.

Уже установленные не перезаписываются — для этого `--force`.

<details>
<summary>Если хочется руками, без npm</summary>

```bash
cd /путь/к/твоему/проекту
mkdir -p .agents/skills .claude/skills
cp -R /путь/к/repomind/skills/docs-* .agents/skills/
for s in .agents/skills/*/; do
  n=$(basename "$s")
  ln -sfn "../../.agents/skills/$n" ".claude/skills/$n"
done
```

На Windows без прав на симлинки — просто скопируй папки в `.claude/skills/`
вместо `ln -s`. В репозитории для этого же лежит `./install.sh`.

</details>

## Использование

| Команда | Что делает | Когда |
|---|---|---|
| `/docs-init` | осмотрит проект и развернёт структуру | один раз на проект |
| `/docs-describe` | опишет архитектуру и API по коду | при `init`, потом по модулям |
| `/docs-task` | ТЗ из Word → папка задачи | приехало новое ТЗ |
| `/docs-plan ABC-123` | технический разбор + оценка в часах | в начале задачи |
| `/docs-do` | выполнит план по шагам, после каждого прогонит тесты | реализация |
| `/docs-sync` | обновит документацию по `git diff` | после реализации |
| `/docs-check` | проверит целостность, пересоберёт каталог | перед коммитом |

В Codex то же самое через `$`: `$docs-init`, `$docs-plan ABC-123`.

Скиллы работают **только с файлами твоего проекта**: читают `docs/`, смотрят
`git diff`, правят markdown. Никуда не ходят по сети и ничего не отправляют
наружу.

### Между `/docs-plan` и `/docs-do` — ты

`/docs-do` не начнёт, пока в шапке `deep-dive.md` не стоит `reviewed: true`.
Прочитал разбор, согласен — поставил. Не согласен — правишь прямо в файле,
агент пойдёт по исправленному.

Это единственная обязательная остановка во всём цикле, и она окупается:

| Где поймал неверный подход | Цена |
|---|---|
| в плане | пара абзацев, 5 минут |
| после реализации | код и тесты заново, полдня |

Дальше `/docs-do` идёт по пунктам, отмечая прогресс сразу, а не в конце:
прервался — продолжит с того же места.

## Что произойдёт при `/docs-init`

Агент сначала **осмотрит проект молча** — определит части, язык, чем
тестируется, есть ли уже документация. Задаст максимум три вопроса, если
что-то осталось непонятным. Дальше создаст:

```text
docs/
├── product/  architecture/  contracts/     каркасы, пустые
├── decisions/     README.md + шаблон ADR
├── runbook/       команды, взятые ИЗ ТВОЕГО проекта
├── requirements/inbox/                     сюда кидать ТЗ
├── tasks/  now/
└── _index.json
AGENTS.md   правила для агентов
CLAUDE.md   одна строка: @AGENTS.md
```

Ключевое: **команды в runbook берутся из настоящих** `Makefile`,
`package.json`, `docker-compose.yml`. Не нашлось — будет написано
`TODO: заполнить`, а не правдоподобная выдумка.

`troubleshooting.md` создастся **пустым**. Так и надо: он пополняется, когда
что-то ломается.

## Чего он не сделает

Сознательно:

- **не перезапишет существующие файлы** — только дозаполнит недостающее;
- **не выдумает архитектуру** — каркасы создаются пустыми, наполнять их
  отдельная работа;
- **не заведёт ADR задним числом** — решения пишутся вперёд;
- **не поставит сторонний софт** — про CodeGraph просто напечатает команду.

Повторный запуск безопасен и полезен: работает как диагностика и дозаполняет
то, чего не хватает.
