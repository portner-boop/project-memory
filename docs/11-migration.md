# 11 — Что менять в текущем flow

Текущий flow стоит **не заменять, а превратить в CLI-протокол**.

## Оставить

- Jira ID как имя директории;
- исходное ТЗ;
- technical deep dive;
- PM-summary;
- план реализации;
- отдельные frontend/backend инструкции;
- документацию в Markdown;
- хранение всего в Git.

## Добавить

| Что                              | Зачем                                             |
| -------------------------------- | ------------------------------------------------- |
| стабильные ID документов и блоков | адресное обновление вместо переписывания файла    |
| `docs/_index.json`               | агент находит нужные документы за один шаг        |
| ADR                              | фиксируется *почему*, а не только *как*           |
| `last_verified_commit`           | видно, что давно не подтверждали                  |
| автоматический `git diff`        | определение влияния без участия человека          |
| structured output от модели      | модель не пишет в файлы напрямую                  |
| `repomind check`                 | дисциплина обеспечивается скриптом, а не памятью  |
| единый cross-agent skill         | один процесс для Claude Code и Codex              |
| CI-проверку                      | забытое обновление ловится в PR                   |

## Убрать

- ручное обновление каталогов;
- полный анализ всей документации после каждой задачи;
- постоянное переключение больших инструкций;
- метки по номерам строк;
- отдельного субагента на каждую мелкую операцию;
- обязательный glossary для каждого проекта.

## Замена меток по номерам строк

Номера строк быстро устаревают. Путь и символ намного стабильнее.

```text
❌ backend/app/auth/service.py:142
✅ backend/app/auth/service.py#AuthService.refresh
```

## Порядок миграции существующего проекта

1. `repomind init` — создаётся каркас, `AGENTS.md`, `CLAUDE.md`.
2. Перенести существующую документацию в `docs/product/`, `docs/architecture/`,
   `docs/contracts/` — **без переписывания текста**.
3. Проставить frontmatter (`id`, `type`, `code_paths`) каждому документу.
4. Разметить блоки `<!-- block: ... -->` там, где документ длиннее одного экрана.
5. `repomind index` — собрать каталог.
6. `repomind check` — увидеть список битых ссылок и недостающих полей.
7. Завести ADR задним числом **только для решений, которые до сих пор спорны**.
   Не нужно восстанавливать историю целиком.
8. Включить CI в check mode.

Шаг 7 — самый частый источник перерасхода времени. ADR пишутся вперёд, а не
назад; ретроспективно фиксируем только то, что реально переспрашивают.
