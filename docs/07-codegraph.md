# 07 — Связка с CodeGraph

[CodeGraph](https://github.com/colbymchenry/codegraph) — локальный индекс кода:
парсит проект через tree-sitter, кладёт символы и связи в SQLite
(`.codegraph/codegraph.db`), отдаёт через MCP и CLI. Заявленная экономия —
47% токенов и 58% вызовов инструментов.

RepoMind использует его как **нижний слой**. Это необязательная зависимость:
нет CodeGraph — всё работает, просто дороже и грубее.

---

## Разделение ролей

```text
┌─────────────────────────────────────────────┐
│  RepoMind    ПОЧЕМУ так и что с этим делать │  ← знание, которого нет в коде
│              решения, требования, процесс   │
├─────────────────────────────────────────────┤
│  CodeGraph   ГДЕ код и как он связан        │  ← извлекается из кода
│              символы, вызовы, зависимости   │
├─────────────────────────────────────────────┤
│  Git         что изменилось                 │
└─────────────────────────────────────────────┘
```

Правило, по которому решается, кто отвечает на вопрос:

> Если ответ **можно вывести из кода** — спрашиваем CodeGraph.
> Если ответ **был только в голове человека** — читаем RepoMind.

---

## Что это даёт: четыре точки стыковки

### 1. `plan` — самый дорогой шаг становится дешёвым

Раздел «Как это работает сейчас» в `deep-dive.md` требует, чтобы агент разобрал
существующий код. Без индекса это десятки `grep` и чтений файлов целиком.

```bash
codegraph explore "расчёт расходов по этапу отчёта"
```

Одна команда возвращает релевантные символы с исходниками, пути вызовов между
ними и сводку blast radius — то есть ровно материал для секции AS IS.

**Было:** ~15 вызовов инструментов, чтение 8 файлов целиком.
**Стало:** 1–2 вызова, в контекст попадают только нужные функции.

### 2. `sync` — поиск задетых документов по графу, а не по маскам путей

Вот главный выигрыш, и он не про деньги, а про **корректность**.

Сейчас документ считается задетым, если изменённый файл попал под его
`code_paths`. Это грубо. Пример:

```text
Изменили:  backend/app/common/periods.py#overlaps

code_paths документа PRODUCT-REPORTS:  backend/app/report/**
                                        ↑ не совпадает → документ пропущен
```

А документ **на самом деле задет**: расчёт расходов вызывает `overlaps`, и если
поменялась семантика границ — описание в документации врёт.

С CodeGraph:

```bash
codegraph impact backend/app/common/periods.py#overlaps
```

возвращает всё, что зависит от символа, включая `calc_stage_expense`. Дальше
скрипт ищет документы, которые ссылаются на любой символ из этого списка —
`PRODUCT-REPORTS` находится.

```text
без CodeGraph:  изменённый файл  →  маска пути      →  документ   (грубо)
с CodeGraph:    изменённый символ →  граф вызовов   →  документ   (точно)
```

Это ловит транзитивные изменения, которые маски пропускают.

### 3. `check` — проверка ссылок на код становится настоящей

Сейчас `/docs-check` проверяет ссылку `path#Symbol` текстовым поиском:
открыть файл, поискать подстроку. Это ловит удалённый файл, но не ловит
переименованный метод внутри другого класса и даёт ложные срабатывания на
совпадениях в комментариях.

```bash
codegraph query calc_stage_expense
```

Проверка идёт по реальному графу символов: символ существует, находится в
указанном файле, это именно функция/метод, а не строка в комментарии.

### 4. `evidence` — проверка честности модели усиливается

Правило «утверждение без доказательства не применяется» держится на проверке
`evidence`. С CodeGraph проверка становится строже:

| Проверка | Без CodeGraph | С CodeGraph |
|---|---|---|
| символ существует | текстовый поиск | запрос к графу |
| символ в изменённых файлах | по diff | по diff |
| **символ реально связан с изменением** | ❌ нельзя проверить | `codegraph impact` |

Третья строка — новая. Модель больше не может сослаться на существующую, но
не относящуюся к делу функцию.

## Как это выглядит в конфиге

`.repomind/config.yml`:

```yaml
codegraph:
  enabled: auto          # auto | on | off
  binary: codegraph      # если не в PATH — полный путь
  impact_depth: 2        # глубина обхода графа при поиске задетых документов
  fallback: glob         # что делать, если индекса нет
```

`auto` — использовать, если `.codegraph/codegraph.db` существует и бинарь
доступен. Иначе тихо откатиться на маски путей.

**Никакой жёсткой зависимости.** Команда `/docs-check` при `enabled: auto`
и отсутствующем индексе выведет одну строку:

```text
note: codegraph не найден, проверка символов идёт текстовым поиском
```

## Новое поле во frontmatter: `symbols`

Чтобы работал поиск по графу, документ должен сообщать не только пути, но и
ключевые символы:

```yaml
---
id: PRODUCT-REPORTS
type: product
code_paths:                                    # грубый слой, работает всегда
  - backend/app/report/**
symbols:                                       # точный слой, нужен CodeGraph
  - backend/app/report/services/expenses.py#calc_stage_expense
  - backend/app/report/serializers/stages.py#StageExpenseSerializer
---
```

Оба поля живут вместе:

- `code_paths` — работает без CodeGraph, ловит грубо, но всегда;
- `symbols` — работает точно и транзитивно, но требует индекса.

`symbols` **не нужно заполнять руками**: `/docs-check` при доступном
CodeGraph сам вытаскивает символы из ссылок вида `path#Symbol` в тексте
документа и складывает их в индекс.

## Первая установка — внутри `/docs-init`

Отдельно поднимать CodeGraph не надо: `/docs-init` делает это сам.

```bash
# один раз на проект
codegraph init             # построить граф
codegraph install          # прописать MCP для Claude Code / Codex

# дальше индекс поддерживает себя сам — file watcher с debounce 2s
```

Обе команды `/docs-init` вызывает за тебя. Как именно — ниже.

### Первичная индексация идёт фоном

На большом репозитории `codegraph init` занимает минуты, а разворачивание
структуры документации — секунды. Поэтому тот же приём, что и в `sync`:
индексация стартует первой и работает **параллельно** со всем остальным.

```text
t0 ├─ проверить окружение
   │
   ├─ codegraph init ──────────┐            ФОНОМ, минуты
   │                            │
t1 ├─ создать AGENTS.md         │           секунды
t2 ├─ развернуть docs/          │
t3 ├─ скопировать скиллы        │
t4 ├─ угадать команды в runbook │
   │                            ▼
t5 ├─ дождаться индексации      ✔
   │
t6 ├─ codegraph install         прописать MCP
t7 ├─ .codegraph/ → .gitignore
t8 └─ codegraph.enabled: on     в .repomind/config.yml
```

Если в проекте **уже была документация** (сценарий миграции), после индексации
`init` дополнительно проходит по ней и заполняет поле `symbols`, вытаскивая
символы из ссылок вида `path#Symbol` в тексте.

### Как выглядит вывод

```text
$ /docs-init

Окружение
  ✔ git-репозиторий
  ✔ codegraph 0.8.1

  ⟳ индексация кода запущена фоном…

Структура
  ✔ AGENTS.md, CLAUDE.md
  ✔ docs/ — 8 каталогов, 6 файлов-каркасов
  ✔ .agents/skills/ — docs-plan, docs-sync
  ✔ .claude/skills/ — symlinks
  ✔ docs/runbook/daily.md — команды угаданы из Makefile и package.json

CodeGraph
  ✔ граф построен: 1240 файлов, 8931 символ, 14с
  ✔ MCP прописан для claude, codex
  ✔ .codegraph/ добавлен в .gitignore
  ✔ codegraph.enabled: on

Дальше:
  1. Поправь docs/runbook/daily.md — команды угаданы, проверь их
  2. Перенеси существующую документацию в docs/product/ и docs/architecture/
  3. /docs-check && /docs-check
```

### Что уже могло быть в проекте

`init` — не установщик, а **инспектор состояния**. Он смотрит, что уже есть, и
дозаполняет только недостающее. Это важно, потому что CodeGraph мог появиться
в проекте раньше RepoMind: кто-то поставил его себе, кто-то закоммитил конфиг,
кто-то уже построил граф.

Проверяется шесть вещей независимо друг от друга:

| Что проверяем | Как |
|---|---|
| бинарь установлен | `codegraph --version` |
| индекс существует | наличие `.codegraph/codegraph.db` |
| индекс свежий | `codegraph status` |
| MCP уже прописан | конфиг агентов |
| `.gitignore` содержит `.codegraph/` | чтение файла |
| в конфиге есть секция `codegraph` | чтение `.repomind/config.yml` |

### Матрица решений

**Бинарь и индекс:**

| Бинарь | `.codegraph/` | Что делает `init` |
|:---:|:---:|---|
| ✖ | ✖ | печатает команду установки, работает на масках |
| ✖ | ✔ | **ничего не удаляет**, сообщает, что индекс осиротел |
| ✔ | ✖ | `codegraph init` фоном |
| ✔ | ✔ свежий | **ничего**, только сообщает статистику |
| ✔ | ✔ устарел | `codegraph sync` — **инкрементально, не полная пересборка** |
| ✔ | ✔ другая схема БД | предлагает `--codegraph rebuild`, сам не пересобирает |

Разница между третьей и последней строкой — минуты против секунд. Полная
пересборка запускается **только** когда индекса нет вообще или его явно
попросили.

**Остальное:**

| Состояние | Что делает `init` |
|---|---|
| MCP уже прописан для обоих агентов | пропускает |
| MCP прописан только для Claude, нужен ещё Codex | дописывает **только** недостающего |
| `.gitignore` уже содержит `.codegraph/` | не дублирует строку |
| `.codegraph/` **закоммичен в git** | предупреждает, предлагает команду, сам не выполняет |
| в конфиге `enabled: off` | **уважает выбор и пропускает всё** |
| в конфиге `enabled: on`, индекса нет | строит индекс |
| секции `codegraph` в конфиге нет | добавляет `enabled: auto` |

### Три правила, которые не нарушаются

**1. Осознанный выбор пользователя сильнее автоопределения.**
`enabled: off` в конфиге означает «я не хочу», а не «я забыл». `init` такое
не переписывает, даже если CodeGraph установлен и индекс лежит рядом:

```text
CodeGraph
  ✔ codegraph 0.8.1, индекс на месте
  — codegraph.enabled: off в конфиге, пропускаю
    (включить: /docs-init --codegraph auto)
```

**2. Ничего не удаляется и не пересобирается без спроса.**
Осиротевший индекс без бинаря — не мусор: человек мог временно снести пакет.
Устаревший индекс чинится инкрементально. Полная пересборка — только по явной
команде.

**3. Изменения в git-индексе — не автоматические.**
Если кто-то закоммитил `.codegraph/`, это надо чинить, но не молча:

```text
  ⚠ .codegraph/ отслеживается git — это производный артефакт,
    он будет конфликтовать при каждом мерже.

    Убрать из индекса, оставив на диске:
        git rm -r --cached .codegraph/

    Строку в .gitignore я уже добавил.
```

Команду печатаем, выполняет человек. Трогать чужую историю коммитов
инструмент не должен.

### Повторный запуск как проверка состояния

Из этого следует удобное свойство: **`/docs-init` на уже настроенном проекте
безопасен и полезен** — он работает как диагностика.

```text
$ /docs-init

Структура
  = AGENTS.md, CLAUDE.md — на месте
  = docs/ — 8 каталогов
  + docs/runbook/release.md — не хватало, создал
  = .claude/skills/ — symlinks целы

CodeGraph
  = codegraph 0.8.1
  ⟳ индекс отставал на 47 файлов — досинхронизировал за 2с
  = MCP прописан для claude, codex
  + .codegraph/ добавлен в .gitignore

Ничего не сломано. Дозаполнено: 2 пункта.
```

Обозначения: `=` уже было · `+` добавлено · `⟳` обновлено · `⚠` требует внимания
· `—` пропущено по настройке.

### Монорепо и нестандартное расположение

Индекс по умолчанию строится от корня репозитория. Если в монорепо нужен
отдельный граф на часть проекта:

```yaml
codegraph:
  root: services/backend      # где строить и искать индекс
```

`init` проверит `.codegraph/` именно там, а не в корне.

### Если CodeGraph не установлен

`init` **не ставит его сам**. Печатает команду и идёт дальше:

```text
Окружение
  ✔ git-репозиторий
  ✖ codegraph не найден

  CodeGraph — необязательный сосед: ускоряет разбор кода и делает
  отбор документов точнее. Без него всё работает на масках путей.

      npm i -g @colbymchenry/codegraph

  Ставить сейчас не буду — глобальный пакет это твоё решение.
  Поставишь позже — запусти `/docs-init` ещё раз, он дозаполнит
  только недостающее.
```

Причина такого поведения — принципиальная, а не перестраховка:

- **установка глобального пакета — решение пользователя**, а не побочный эффект
  чужой команды;
- у CodeGraph есть установка вида `curl … | sh`; **скачивать и исполнять
  удалённый скрипт от имени пользователя инструмент не должен** никогда,
  даже когда источник выглядит доверенным;
- в CI это тем более вредно — там установка описана явно в workflow.

Поэтому максимум, что делает `init`, — показывает команду. Тот же принцип
работает и в обратную сторону: `/docs-init` идемпотентен, повторный запуск
дозаполняет недостающее и ничего не ломает.

### `.codegraph/` в `.gitignore`

```gitignore
.codegraph/          # локальный индекс кода, пересобирается из исходников
.repomind/dirty      # маркер «были правки»
```

Индекс — производный артефакт, он не коммитится: у каждого свой, весит много
и протухает мгновенно. В CI кешируется отдельно, средствами CI.

### Флаг

```bash
/docs-init --codegraph auto|skip|rebuild
```

| Значение | Что делает |
|---|---|
| `auto` | по умолчанию: смотрит на состояние и дозаполняет недостающее |
| `skip` | не трогать вообще, даже если установлен |
| `rebuild` | полная пересборка индекса; единственный способ её запустить |

`skip` нужен, когда индекс поднимают централизованно или проект слишком большой
для локального графа. `rebuild` — после обновления CodeGraph со сменой схемы БД
или когда граф явно поехал.

Флаг перекрывает конфиг на один запуск, но **не переписывает** `enabled: off` в
`.repomind/config.yml` — чтобы включить насовсем, надо поправить конфиг.

## Поддержание индекса

RepoMind ничего не пересобирает: если CodeGraph следит за файлами, к моменту
`/docs-sync` индекс уже актуален. Если watcher не запущен, `sync` вызовет
`codegraph sync` сам — [параллельно вызову модели](#параллельная-переиндексация-во-время-sync).

## Параллельная переиндексация во время `sync`

Проблема: к моменту, когда `sync` проверяет `evidence`, граф обязан быть
свежим — иначе проверка пойдёт по старым символам, а только что добавленной
функции в нём ещё нет.

Решение: **запускать переиндексацию одновременно с вызовом модели**, а не до
него. Вызов модели занимает десятки секунд, инкрементальный `codegraph sync` —
единицы. Переиндексация успевает закончиться внутри этого окна и по времени
обходится в ноль.

```text
t0 ├─ git diff                                   быстро
   │
   ├─ codegraph sync ──────────┐                 ФОНОМ
   │                            │
t1 ├─ классификация изменений   │                по путям, граф не нужен
   │                            │
t2 ├─ отбор блоков документации │                по старому индексу — ок
   │                            │
t3 ├─ ВЫЗОВ МОДЕЛИ ═══════════  │                10–30 секунд
   │  (пишет, что сделано)      │
   │                            ▼
t4 ├─ дождаться переиндексации  ✔                обычно уже готова
   │
t5 ├─ проверка evidence по СВЕЖЕМУ графу
   │
t6 └─ применить операции, записать result.md
```

Ключевой момент — **что можно делать по старому графу, а что нельзя**:

| Шаг | Нужен свежий граф | Почему |
|---|:---:|---|
| классификация изменений | ❌ | работает по путям из diff |
| отбор задетых документов | ❌ | ищем, что зависело от изменённого кода **до** правки |
| вызов модели | ❌ | ей отдают diff, а не граф |
| **проверка `evidence`** | ✅ | новых символов в старом графе нет |
| `codegraph impact` для новых функций | ✅ | то же самое |

Отбор документов **сознательно идёт по старому графу**: нас интересует, кто
зависел от изменённого кода до правки, — именно эти документы могли устареть.

### Настройка

```yaml
codegraph:
  reindex_on_sync: parallel   # parallel | before | off
```

| Значение | Когда использовать |
|---|---|
| `parallel` | по умолчанию: фоном, параллельно вызову модели |
| `before` | последовательно, до всего; для отладки и CI |
| `off` | watcher точно работает, переиндексация не нужна |

Если `codegraph status` показывает, что индекс уже актуален (watcher отработал),
запуск пропускается — лишней работы не будет.

### Отдельно про CI

В CI file watcher не запущен, поэтому там всегда:

```bash
codegraph init          # или sync, если .codegraph/ закеширован между запусками
/docs-check --strict
```

Кеширование `.codegraph/` между запусками CI превращает `init` в быстрый `sync`.

## Что НЕ надо отдавать CodeGraph

Соблазн: «раз есть граф — давайте генерировать документацию из него».
Не надо. Граф знает структуру, но не знает смысла.

| Вопрос | Кто отвечает |
|---|---|
| где определён `ContestService` | CodeGraph |
| кто вызывает `calc_stage_expense` | CodeGraph |
| что сломается при изменении сигнатуры | CodeGraph |
| почему отказались от Celery | **RepoMind** |
| заказчик просил пересечение или дедлайн | **RepoMind** |
| что решили **не** делать в прошлой задаче | **RepoMind** |
| сколько заняла похожая задача | **RepoMind** |
| как поднять проект с нуля | **RepoMind**, [runbook](02-doc-model.md#runbook--инструкции-по-запуску) |

Граф отвечает на «что» и «где». Документация — на «почему» и «как правильно».

---

## Что меняется в цифрах

Грубая прикидка на задаче среднего размера:

| Шаг | Без CodeGraph | С CodeGraph |
|---|---|---|
| `plan`, сбор AS IS | 8–15 чтений файлов | 1–2 запроса к графу |
| `sync`, отбор документов | по маскам, с промахами | по графу, транзитивно |
| `check`, проверка ссылок | текстовый поиск | запрос к графу |

Экономия складывается с экономией самого RepoMind, и они не пересекаются:
RepoMind сокращает **объём документации** в контексте, CodeGraph — **объём
кода**.

---

## Если CodeGraph нет

Всё работает. Деградация:

| Возможность | Без индекса |
|---|---|
| отбор документов | только по `code_paths`, транзитивные связи теряются |
| проверка `path#Symbol` | текстовый поиск, возможны ложные срабатывания |
| сбор AS IS в `plan` | обычные чтения файлов, дороже |
| всё остальное | без изменений |

Поэтому `code_paths` остаётся обязательным полем, а `symbols` —
дополнительным. Система не должна разваливаться из-за отсутствия соседнего
инструмента.
