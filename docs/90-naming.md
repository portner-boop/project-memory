# 02 — Название и позиционирование

## Выбранное имя: RepoMind

Смысл понятен сразу:

- **Repo** — документация живёт рядом с кодом;
- **Mind** — это память проекта для человека и агента;
- подходит для Claude Code, Codex и других coding agents;
- короткое, читается вслух, годится и для скиллов, и для будущего пакета.

> **Замечание о `docflow`.** В исходном описании детальная часть была
> написана с командами вида `docflow sync`. Это рабочее имя-синоним;
> канон — **RepoMind**. Скиллы называются `docs-*`, npm-пакет —
> `repomind-skills` (имя `repomind` в npm уже занято другим проектом).

## Рассмотренные варианты

| Вариант          | Акцент                                                          |
| ---------------- | --------------------------------------------------------------- |
| **RepoMind**     | документация рядом с кодом + память для человека и агента        |
| **ContextFlow**  | автоматическое движение и обновление контекста                   |
| **Project Memory** | максимально понятное позиционирование                          |
| **CodeContext**  | документация как контекст для разработки                         |
| **DocSync**      | простое название, но слишком общее                               |
| **SpecFlow**     | акцент на ТЗ и планах                                            |
| **RepoContext**  | точное техническое название                                      |
| **LivingDocs**   | постоянно обновляемая документация                               |
| **ContextLedger**| журнал знаний, решений и изменений                               |
| **AgentDocs**    | понятно, но привязывает продукт только к агентам                 |
| **ProjectBrain** | звучит ярко, но менее технически                                 |
| **CodeMemory**   | память кодовой базы                                              |
| **Continuum Docs** | документация, непрерывно развивающаяся вместе с проектом       |

## Топ-5 с обоснованием

1. **RepoMind** — лучший вариант для продукта.
2. **ContextFlow** — лучший вариант для инфраструктурного инструмента.
3. **Project Memory** — лучше всего объясняет идею.
4. **SpecFlow** — подходит для текущего Jira-flow.
5. **LivingDocs** — лучше всего отражает автоматическое обновление.

## Как использовать имена вместе

- Продукт: **RepoMind**.
- Слоган: *документация, которая развивается вместе с кодом*.
- Расширенное описание: *инкрементальная память проекта для разработчиков
  и coding agents*.
- «Project Memory» удобно использовать в объяснениях для людей, которые
  впервые слышат про инструмент, — как жанр, а не как бренд.
