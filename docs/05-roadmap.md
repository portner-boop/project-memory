# 05 — Что дальше

## Сейчас: шесть скиллов

Всё работает на скиллах — обычных markdown-файлах с инструкцией для агента.
Ни сервера, ни базы, ни API-ключей: думает тот агент, за которого ты уже
платишь.

```bash
npx repomind-skills
```

| Скилл | Готов |
|---|:---:|
| `/docs-init` | ✅ |
| `/docs-task` | ✅ |
| `/docs-plan` | ✅ |
| `/docs-do` | ✅ |
| `/docs-sync` | ✅ |
| `/docs-check` | ✅ |

**Что сейчас важнее всего:** обкатать их на реальных задачах и править
`SKILL.md` под свой процесс. Скиллы настраиваются итерациями — первый разбор
почти наверняка выйдет хуже того, что ты пишешь руками. Вот тогда и надо
дописывать в инструкцию то, чего не хватило.

## Дальше — по мере надобности

Ничего из этого не обязательно. Включается, когда реально мешает отсутствие.

### Хуки

Схема «дешёвое часто, дорогое редко»:

```text
правка файла   →  PostToolUse    →  touch .repomind/dirty     бесплатно
задача готова  →  TaskCompleted  →  /docs-sync                1 вызов модели
перед коммитом →  git pre-commit →  /docs-check               бесплатно
```

Первый уже лежит в примере:
[.claude/settings.json](../examples/demo-project/.claude/settings.json).

⚠️ Не вешать sync на `Stop` — он срабатывает после каждого ответа модели.

### CodeGraph

Ускоряет разбор кода и делает отбор задетых документов точнее — по графу
вызовов вместо масок путей. Необязательная зависимость.
→ [07 — Связка с CodeGraph](07-codegraph.md)

### CI

Смысл появляется, когда в команде больше одного человека и кто-то забывает
прогнать `/docs-check` перед PR.

Оба агента умеют работать headless: Claude Code через `claude -p`,
Codex через `codex exec`. Этого достаточно, чтобы прогнать проверку на PR
и сообщить, что документация отстала.

**Два режима, и путать их не надо:**

| Режим | Что делает | Когда включать |
|---|---|---|
| **Check** | сообщает, что устарело, проваливает PR | сразу, безопасно |
| **Fix** | создаёт патч или отдельный PR | по метке, вручную |

**CI не должен автоматически менять основную ветку.** Fix-режим вешается на
метку в PR — так у человека остаётся контроль над тем, когда модель пишет
в репозиторий.

### Jira и GitHub

Когда надоест перетаскивать `.docx` руками. Здесь появляется MCP или прямая
интеграция:

```text
Jira → /docs-task → реализация → PR → summary обратно в Jira
```

До этого момента MCP не нужен: агент и так читает файлы и запускает git.

### Пакет с логикой вместо инструкций

Часть работы скиллов — чистая механика: собрать `_index.json`, проверить
ссылки, аккуратно заменить блок в markdown. Это можно вынести в программу,
которую агент будет вызывать как `git` или `npm`.

Смысл появится, когда:

- проверки станут заметно медленными на большом репозитории;
- захочется гонять валидацию в CI без агента;
- надоест, что один и тот же обход `docs/` каждый раз делается заново.

Пока ни одна из трёх причин не наступила — **скиллов достаточно**, и лишняя
зависимость только усложнит установку.

## С чего начать лично тебе

Если раньше не настраивал агентов — порядок такой:

1. **`npx repomind-skills` и `/docs-init`** на рабочем проекте. Полчаса.
2. **Поправь `docs/runbook/daily.md`** — команды угаданы, проверь их.
3. **Возьми следующую реальную задачу** и пройди `/docs-plan` → прочитка →
   `/docs-do` → `/docs-sync`. Не тестовую, а настоящую.
4. **Сравни разбор с тем, что пишешь руками.** Чего не хватило — допиши
   в `SKILL.md`.
5. **Первый ADR** заведи, когда кто-то спросит «а почему тут так?». Не раньше.
6. **Хуки и CI** — когда надоест вызывать руками.

Шаг 3 — главный. Скиллы настраиваются на реальной работе, а не на примерах.
