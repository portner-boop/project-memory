# 04 — Скиллы

Шесть скиллов. Каждый — папка с `SKILL.md`, обычным markdown-файлом
с инструкцией для агента.

| Скилл | Что делает | Модель думает |
|---|---|:---:|
| `/docs-init` | разворачивает структуру под твой стек | ✅ |
| `/docs-task` | ТЗ из Word → папка задачи | ❌ механика |
| `/docs-plan` | разбор кода, план, оценка в часах | ✅ |
| `/docs-do` | выполняет прочитанный план по шагам | ✅ |
| `/docs-sync` | обновляет документацию по `git diff` | ✅ |
| `/docs-check` | валидация + пересборка каталога | ❌ механика |

В Codex — через `$`: `$docs-plan ABC-123`.

Без аргументов скиллы берут текущую задачу из `docs/now/current-task.md`.

## Установка

```bash
npx repomind-skills
```

Кладёт скиллы в `.agents/skills/` (оттуда их читает Codex) и делает symlinks
в `.claude/skills/` (оттуда — Claude Code). На Windows без прав на symlink
копирует папки.

Уже установленные не перезаписываются, для этого `--force`.

## `/docs-init`

Отвечает на вопрос «а откуда возьмутся папки, ADR и всё остальное».

### Что появляется в проекте

```text
✔ AGENTS.md                              правила для агентов, под твой стек
✔ CLAUDE.md                              одна строка: @AGENTS.md

✔ .repomind/config.yml                   настройки проекта
✔ .gitignore                             += .repomind/dirty, .codegraph/

✔ docs/README.md                         навигация
✔ docs/_index.json                       пустой каталог
✔ docs/product/          + README.md
✔ docs/architecture/     + README.md
✔ docs/contracts/        + README.md
✔ docs/decisions/README.md               ЧТО ТАКОЕ ADR и когда его писать
✔ docs/decisions/_template.md            болванка ADR
✔ docs/runbook/setup.md                  каркас: как поднять проект
✔ docs/runbook/daily.md                  каркас: тесты, линтеры, миграции
✔ docs/runbook/troubleshooting.md        пустой, заполняется по мере поломок
✔ docs/runbook/release.md                каркас: порядок выкатки
✔ docs/requirements/inbox/README.md      сюда кидать .docx
✔ docs/requirements/original/
✔ docs/tasks/
✔ docs/now/current-task.md               заглушка
```

Файлы `runbook/` создаются **каркасом с настоящими командами**: скилл смотрит
на `Makefile`, `package.json`, `manage.py`, `docker-compose.yml` и подставляет
то, что нашёл. Не нашёл — пишет `TODO: заполнить`, а не правдоподобную выдумку.

`troubleshooting.md` создаётся **пустым**. Так и надо: он пополняется, когда
что-то ломается.

### Три правила

1. **Существующие файлы не перезаписываются.** Только дозаполняется недостающее.
2. **Архитектурные документы создаются пустыми.** Наполнять их — отдельная
   работа, выдумывать архитектуру скилл не будет.
3. **Максимум три вопроса**, и все сразу. Остальное определяется из проекта.

### Повторный запуск = диагностика

Раз ничего не ломается — запускать на настроенном проекте полезно:

```text
Структура
  = AGENTS.md, CLAUDE.md — на месте
  + docs/runbook/release.md — не хватало, создал
  = .claude/skills/ — symlinks целы

CodeGraph
  ⟳ индекс отставал на 47 файлов — досинхронизировал за 2с

Ничего не сломано. Дозаполнено: 2 пункта.
```

`=` было · `+` добавлено · `⟳` обновлено · `⚠` внимание · `—` пропущено.

### CodeGraph

Если [CodeGraph](07-codegraph.md) установлен, `/docs-init` поднимет и его.
Не установлен — покажет команду и пойдёт дальше, сам ставить не будет.
Матрица состояний — [07](07-codegraph.md#что-уже-могло-быть-в-проекте).

## `/docs-task` — загрузка ТЗ

Главный сценарий: **ТЗ приходит в Word**.

### Основной способ

```text
1. Перетаскиваешь ABSHTRUE-657.docx в docs/requirements/inbox/
2. Говоришь агенту:  /docs-task
```

Что происходит:

```text
docs/requirements/inbox/ABSHTRUE-657.docx
        │
        ├─ определить ID          из имени файла по шаблону [A-Z]+-\d+
        ├─ конвертировать         .docx → markdown (таблицы, списки, картинки)
        ├─ картинки               → requirements/original/ABSHTRUE-657.assets/
        │
        ├─ сохранить оригинал     → requirements/original/ABSHTRUE-657.docx
        ├─ сохранить markdown     → requirements/original/ABSHTRUE-657.md
        ├─ создать папку задачи   → tasks/ABSHTRUE-657/request.md
        ├─ обновить               → now/current-task.md
        └─ очистить inbox
```

Оригинальный `.docx` **сохраняется рядом**: если конвертация что-то потеряла,
всегда можно открыть исходник. Кинул пять файлов — обработаются все пять.

### Определение номера задачи

1. имя файла — `ABSHTRUE-657.docx`, `ТЗ ABSHTRUE-657 v2.docx`;
2. первые 20 строк текста;
3. спросят.

Шаблон настраивается в `.repomind/config.yml`:

```yaml
task:
  id_pattern: "[A-Z]+-\\d+"
  jira_base_url: "https://jira.company.ru/browse/"
```

### Другие способы

```text
/docs-task ABSHTRUE-657 путь/к/файлу.docx   — файл не в inbox
/docs-task ABSHTRUE-657                     — вставить текст прямо в чат
```

### Форматы и что теряется

| Формат | Как конвертируется |
|---|---|
| `.docx` | `markitdown`, запасной вариант — `mammoth` |
| `.pdf` `.xlsx` | `markitdown` |
| `.md` `.txt` | как есть |

Честно, чтобы не было сюрпризов:

- **схемы и диаграммы** превращаются в картинку, текст с них не считывается;
- **сложные объединённые ячейки** могут поехать;
- **комментарии на полях** и правки в режиме рецензирования теряются.

Поэтому оригинал и лежит рядом. Скилл обязан **явно сказать**, что потерялось.

## `/docs-plan`

Читает ТЗ, отбирает **только** документы с пересекающимися `code_paths`,
читает реальный код этих модулей и пишет три файла:

| Файл | Для кого |
|---|---|
| `deep-dive.md` | разработчик и агент: AS IS, код, риски, план |
| `estimate.md` | ты и менеджер: часы с разбивкой и допущениями |
| `summary.md` | все остальные: 3 абзаца без путей к файлам |

Заканчивается передачей на прочитку и ставит `reviewed: false`.

Планка качества `deep-dive.md` зашита в
[SKILL.md](../skills/docs-plan/SKILL.md) — обязательные разделы, ссылки
`path:line`, список «не трогаем», пронумерованные риски.

## `/docs-do`

Не начнёт, пока в шапке `deep-dive.md` не стоит `reviewed: true`.

Дальше идёт по чеклисту **по одному пункту**, отмечая в `progress.md` сразу,
а не в конце: прервался — продолжит с того же места.

Понял, что пункт неверен — **останавливается и спрашивает**, а не переписывает
план молча.

Тесты и линтеры **не запускает** — это твоё решение и твои команды,
они в `docs/runbook/daily.md`.

## `/docs-sync`

Смотрит `git diff`, определяет, что изменилось по смыслу, отбирает связанные
блоки документации и правит **только их**. Подробно, по шагам —
[03 — Полный цикл](03-workflow.md#этап-4-синхронизация--подробно).

Ключевое: модель не пишет в файлы напрямую, она возвращает **операции**,
которые проверяются до применения. Схема ответа —
[sync-operations.schema.json](../skills/docs-sync/schemas/sync-operations.schema.json).

---

## `/docs-check`

Пересобирает `docs/_index.json` и проверяет **без всякого рассуждения**:

уникальность ID документов и блоков · существование всех `path#Symbol` ·
битые markdown-ссылки · `code_paths` указывают на существующие пути ·
обязательные файлы задачи · полнота frontmatter · пустые блоки ·
протухший `last_verified_commit` · конфликтующие ADR · номера строк
в постоянной документации · размер `AGENTS.md`

Ошибки и предупреждения раздельно. **Найденное не чинит молча** — сообщает.
