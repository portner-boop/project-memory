# 01 — Как это работает

Если ты раньше не настраивал агентов — читай подряд, тут с нуля.

---

## Почему всё крутится вокруг контекста

Одна вещь, из которой следует вся конструкция:

> **Агент ничего не помнит между сессиями. Каждый раз он начинает с нуля.**

Всё, что агент «знает» о проекте — это текст, физически загруженный в окно
контекста прямо сейчас. Окно конечное. Каждый токен стоит денег и размывает
внимание модели.

Отсюда два следствия:

1. **Знания надо хранить снаружи.** Файлы в репозитории — самое надёжное место:
   версионируются, ревьюятся, не пропадают.
2. **Загружать надо не всё, а нужное.** Если на каждую задачу грузить всю
   документацию — расход растёт вместе с проектом. Задача «поменять сортировку
   отчётов» не должна тянуть за собой документ про авторизацию.

RepoMind — это ответ на вопрос: **как хранить знания так, чтобы агент забирал
ровно нужный кусок.**

---

## Четыре механизма, которые обычно путают

Они отвечают на **разные вопросы**.

| Механизм | Вопрос | Аналогия |
|---|---|---|
| `AGENTS.md` / `CLAUDE.md` | что помнить **всегда** | правила на стене офиса |
| **Skill** | **как** делать процедуру | инструкция в папке на полке |
| **Hook** | **когда** запустить скрипт | автоматический выключатель |
| **MCP** | **откуда** взять внешние данные | пропуск в соседнее здание |
| **Субагент** | **кто** сделает параллельно | коллега, которому делегировал |

### AGENTS.md — постоянная память правил

Файл, который агент читает **сам при каждом старте**, без команд.

- **Codex** читает `AGENTS.md`.
- **Claude Code** читает `CLAUDE.md`.
- Чтобы не дублировать, `CLAUDE.md` содержит одну строку `@AGENTS.md` — это
  синтаксис импорта у Claude Code.

**Ограничение:** файл грузится в каждую сессию и ест контекст постоянно.
Туда кладут только короткие вечные правила, не документацию.
Лимит проектных инструкций у Codex — 32 KiB, `CLAUDE.md` Anthropic советует
держать до ~200 строк.

Пример: [examples/demo-project/AGENTS.md](../examples/demo-project/AGENTS.md) — 40 строк,
это правильный размер.

### Skill — процедура, которая грузится по требованию

**Skill сам по себе не срабатывает по событию.** Это не триггер, а папка с
инструкцией:

```text
.agents/skills/docs-sync/
└── SKILL.md
```

В начале файла — frontmatter:

```md
---
name: docs-sync
description: Incrementally update project documentation from a git diff...
---
```

**Два пути попадания в работу:**

**А. Ты вызываешь руками** — пишешь `/docs-sync`, агент открывает файл и следует
инструкции.

**Б. Агент решает сам** — тут работает *progressive disclosure*:

```text
всегда в контексте:  name + description каждого скилла   ← ~30 токенов, дёшево
грузится по нужде:   полное тело SKILL.md                ← сотни строк, дорого
```

Агент видит только короткие описания, как оглавление книги. Ты говоришь «обнови
доки по задаче» — он узнаёт своё в `docs-sync` и **только тогда** читает файл
целиком.

Поэтому `description` — это не документация для человека, а **условие
срабатывания для модели**. Плохой description = скилл никогда не подхватится.

**Почему один скилл на двух агентов.** Codex ищет скиллы в `.agents/skills/`,
Claude Code — в `.claude/skills/`. Оба понимают symlink:

```bash
ln -s ../../.agents/skills/docs-sync .claude/skills/docs-sync
```

Настоящий файл лежит один раз. `repomind init` делает это за тебя
(на Windows — копирует).

### Hook — вот что реально «срабатывает»

**Хук — это не про ИИ.** Обычный shell-скрипт, который Claude Code запускает
сам при событии. Модель не участвует: «случилось X → выполни команду».

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "touch .repomind/dirty" }]
      }
    ]
  }
}
```

«После каждого применения Edit или Write — выполни `touch .repomind/dirty`».

Событий около тридцати, тебе нужны четыре:

| Событие | Когда стреляет |
|---|---|
| `PostToolUse` | после того как агент применил инструмент |
| `Stop` | **после каждого ответа модели** ⚠️ |
| `TaskCompleted` | когда задача помечается выполненной |
| `SessionEnd` | при закрытии сессии |

⚠️ **Главная ловушка.** `Stop` срабатывает на **каждый ответ**, а не в конце
работы. Повесишь туда полный `repomind sync` — модель ответила «ок, сейчас
посмотрю», и уже улетел LLM-вызов и деньги.

Отсюда правило — **дешёвое часто, дорогое редко**:

```text
правка файла   →  PostToolUse    →  touch .repomind/dirty     бесплатно, 100 раз за сессию
задача готова  →  TaskCompleted  →  repomind sync             1 вызов модели
перед коммитом →  git pre-commit →  repomind check            бесплатно
```

Флаг `dirty` — пустой файл-маркер «тут меняли, синк не делали».

Отдельно: `pre-commit` — это **не** хук Claude Code, такого события нет. Это
стандартный git-хук, и он работает независимо от того, кто делал коммит — ты
руками или агент. Так даже надёжнее.

### MCP — розетка во внешний мир

Нужен, когда агенту надо дотянуться **за пределы репозитория**: Jira,
Confluence, GitHub API, база.

Для локальных файлов MCP **не нужен** — агент и так читает файлы и запускает git.
В первой версии его нет.

Общее правило: **не подключай MCP там, где хватает файла на диске.** Каждый
MCP-сервер держит описания своих инструментов в контексте постоянно.

### Субагент — делегирование

Отдельный экземпляр агента со своим чистым контекстом. Полезен, когда надо
параллельно изучить фронт и бэк и не засорять основной контекст.

Дорого. В исходной идее, от которой мы отталкивались, было четыре субагента на
каждое обновление доков — это сознательно выкинуто. Субагент — для крупного
разбора, не для рутинного синка.

## Итоговая формула RepoMind

Не «умный агент с четырьмя субагентами», а гибрид: **дорогое — модели,
дешёвое — скриптам**.

```text
Git и скрипты
    ↓
находят изменения и нужные документы
    ↓
один короткий вызов LLM
    ↓
возвращает структурированные операции
    ↓
скрипты применяют и проверяют изменения
    ↓
человек видит обычный Git diff
```

Из шести этапов цикла модель работает на двух. Остальное — детерминированный код.

| Компонент | Роль |
|---|---|
| `AGENTS.md` | короткие постоянные правила |
| `CLAUDE.md` | импортирует `AGENTS.md`, своего не хранит |
| Skill | хранит процесс |
| Hook / CI | запускает процесс |
| MCP | только внешние источники |
| Субагенты | только крупные задачи |

---

## Главный экономический эффект

> Расход токенов зависит **от размера изменения, а не от размера проекта**.

В модель уходит только: задача, изменённые куски кода, сигнатуры изменённых
функций, связанные блоки документации, текущий план.

Не уходит: весь репозиторий, вся документация, другие задачи, git history.

На репозитории в миллион строк синк стоит столько же, сколько на десяти тысячах.
